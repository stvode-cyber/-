## FD-001 AI 记忆库（Vault）
- 说明：为每个用户提供独立的 Obsidian 风格记忆库（vault_notes 表），支持自动提取、对话注入、用户手动管理、跨设备持久化
- 注释：
  - 存储：服务端数据库 per-user 严格隔离，Markdown + YAML frontmatter，分类「人物/偏好/事项/时间线/其他」，userId+title 唯一约束
  - 采集：每次对话后 DeepSeek 异步提取长期记忆（关系/偏好/重要事项），跳过临时指令和闲聊
  - 注入：对话时按关键词匹配 + pinned notes 保底注入 LLM 上下文
  - 控制：设置页 VaultPage 查看/搜索/编辑/删除/手动添加
  - 安全：JWT 鉴权 + 写操作限流 + LLM 输出 JSON 白名单校验
  - 大坑：vaultService.ts 异步处理不可阻塞对话响应
- 目标：G-个性化体验 / VG-AI 记住用户
- 关联：
  ↔ Dc-放弃本地文件存储方案，改用服务端数据库（多设备一致性）
  ↔ Dc-异步采集避免阻塞对话
  ↔ Dc-Pinned notes 保底机制
  ↔ A-vaultService.ts 采集逻辑
  ↔ A-llmService.ts 注入逻辑 L157-161

## FD-002 远程文件访问（remoteFileServer + frp 内网穿透）

- 说明：让手机等外部设备通过公网 H5 页面访问本机白名单目录的文件（桌面/文档/下载/图片），远程取文件不靠网盘
- 注释：
  - 链路：手机 → 47.116.59.141:3900 → frp 隧道 → 本机 127.0.0.1:3900
  - 服务端：remoteFileServer 独立端口 3900 绑 0.0.0.0（用户显式开启），配置持久化在数据目录 remote-access.json；主后端仍绑 127.0.0.1
  - 安全：6 位访问码（去易混淆字符）换 12h 令牌，认证失败限流 5 次/分钟/IP；路径必须过 safeResolve 白名单
  - 默认关闭：设置页开关 enabled:false 时链路虽通但应用侧不响应
  - 配套：frps v0.61.1 云服务器 systemd 自启（bindPort 7000 + token）；本机 frpc 开机自启（Startup/frpc-tunnel.vbs）
  - 大坑：阿里云安全组要放行入方向 TCP 7000(隧道)+3900(文件)；重生成访问码会轮换令牌密钥，所有手机端立即下线
- 目标：VG-跨设备取文件
- 关联：
  ↔ Dc-远程文件服务独立端口+访问码+目录白名单，主后端不暴露公网
  ↔ Dc-frp 隧道方案（云服务器中转），frpc 开机自启
  ↔ A-remoteFileServer.ts / remoteFilePage.ts
  ↔ A-frpc.toml 隧道 aie-remote-file

## FD-003 登录失败常驻提示条（LoginPage）
- 说明：登录/注册失败（密码错了、账号不存在、验证码错误、注册冲突等）在表单内立即显示红色常驻提示条，不再只依赖顶部 2 秒 toast（用户反馈"密码错了没提示"）
- 注释：
  - 实现：LoginPage 新增 formError state + ErrorBanner 组件（桌面/移动两套配色），handleLoginFail / onSubmit / onPhoneRegister / onSendSms 失败分支统一 setFormError，成功与切换模式/重新输入时清除
  - 保留原 toast 双保险：toast 仍弹，但错误条常驻到用户修正输入
  - 差异化文案沿用原逻辑：第 1 次"用户名或密码错误"→ 第 2 次提示检查大小写 → 3 次起提示"忘记密码" → 5 次起建议联系管理员
  - 大坑①：Electron 开发模式跑的是 electron/resources/backend|frontend/dist（编译产物拷贝），源码改动后必须 npm run build / npx tsc 并重新拷贝同步，否则界面一直是旧版
  - 大坑②：PowerShell Set-Content -Encoding UTF8 会写 BOM，remote-access.json 等被 JSON.parse 的文件会解析失败回退默认值（服务不启动）；要用 UTF8Encoding($false)/[IO.File]::WriteAllText 无 BOM 写入
  - 大坑③（注册页输入失焦"按1个数字需再次点击"）：LoginPage 内部定义的组件（ErrorBanner/PhoneRegisterSection/ForgotDialog）每次渲染组件类型都变，React 卸载重挂整棵子树导致输入框失焦；必须全部提取为模块顶层组件 + props 传参，修后重新构建并同步 dist 生效（2026.09.02 v2026.09.02.1508 发布）
- 目标：VG-基础可用性 / 人设-指令必落地
- 关联：
  ↔ E-用户反馈"提示缺少提示条，密码错了要提示"
  ↔ Dc-提示条采用表单内常驻 + toast 双通道（避免 toast 短暂被忽略）
  ↔ A-LoginPage.tsx handleLoginFail / ErrorBanner
  ↔ A-前端 dist 同步 electron/resources/frontend/dist

## FD-004 自动更新（轻量自更新：frp 公网链路分发）
- 说明：以后所有更新（前端/后端/schema）都自动完成：发布脚本打更新包到公网链路 → 应用每次启动自动检查、下载、sha256 校验、应用、重启生效，用户无感，不再手动重装升级包
- 注释：
  - 链路：publish-update.cjs 构建 → 打 zip + sha256 → 写入 <userData>/updates → remoteFileServer 新增 /updates 静态路由（公开只读、白名单仅 3 个文件名）→ 外网经 frp 隧道 http://47.116.59.141:3900/updates 拉取
  - 基线：electron/resources/.version.json 记录已应用版本与各 part 的 sha256；publish 时同步写本地基线，本机以此判定"无更新"（幂等）；发布脚本同步前后端产物到 electron/resources，保证本机也最新
  - 流程：main.cjs 启动 → 后端就绪后 fetchRemote（检查/下载/校验）→ applyIfNewer（备份→解压→写基线）→ 有变更 relaunch 重启生效；更新源不可达/异常静默跳过，不影响启动
  - 覆盖三端：frontend(dist)、backend(dist)、schema.prisma（复制到后端资源目录 + 重新生成 Prisma Client）
  - 大坑①：schema 更新时后端正在运行，query_engine-windows.dll.node 被进程锁定，原地 prisma generate 会 EPERM 失败；改为写 .prisma-regenerate 标记，下一次冷启动（后端未启动、无锁）由 main.cjs 执行重新生成（已验证修复）
  - 大坑②：更新包必须含前端编译产物（源码改动后 npm run build + 同步到 electron/resources/frontend/dist），否则界面仍是旧版
- 目标：VG-持续交付（更新零手工操作）
- 关联：
  ↔ A-updater.cjs（fetchRemote / applyIfNewer / regeneratePrismaIfMarked）
  ↔ A-publish-update.cjs（构建→打包→发布→写基线）
  ↔ A-main.cjs 启动接线（预启动处理标记 → 启动后端 → 更新检查 → 重启）
  ↔ A-remoteFileServer.ts /updates 静态路由（与远程文件访问共用 3900 端口）
  ↔ Dc-复用 frp 公网链路做更新源，零新增云服务/域名依赖
  ↔ Dc-版本基线 sha256 对比决定是否更新，幂等可回滚（备份 .bak 兜底）
