# 宠物系统（QQ 宠物式陪伴）

> 整合来源：`PET_INTEGRATION.md` + `PET_SHOP_FEATURE.md` + `PET_CHECKIN_FEATURE.md` + `PET_EVOLUTION_FEATURE.md`
> 范围（MVP）：桌面陪伴宠物 + 后端账号绑定（多端同步）+ 3D 视觉 + 装扮商店 + 每日签到 + 成长进化。

## 一、数据模型（Prisma）

`Pet`（与 `User` 1:1，`userId` 唯一）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `userId` | String @unique | 归属用户 |
| `name` | String | 昵称，默认「豆豆」，1-12 字 |
| `species` | String | `cat` \| `dog` \| `blob`（决定 3D 外观） |
| `level` / `exp` | Int | 等级 / 经验（升级阈值 = `level*100`） |
| `hunger` / `mood` / `clean` / `energy` | Int 0-100 | 四维状态 |
| `coins` | Int | 互动/签到获得的金币 |
| `lastUpdated` | DateTime | 衰减基准时间 |
| `lastCheckinDate` | String | 本地 `YYYY-MM-DD`，签到日期 |
| `checkinStreak` | Int | 连续签到天数 |
| `checkinTotal` | Int | 累计签到天数 |
| `equipped` | String (JSON) | 5 槽位装扮（帽子/眼镜/项圈/玩具/背景） |

衰减常量（每分钟）：`hunger 0.2 / mood 0.15 / clean 0.2 / energy 0.1`，实时按 elapsed 折算（GET 不落库，互动前折算后写回）。

`PetOwnedItem`：用户持有的装扮（`userId + itemKey` 唯一，标量字段，不与 `User` 建强关联）。

> 注：因 `PetOwnedItem` 仅用标量 `userId` 字段，删除用户时**不会级联**，须在清理脚本中 `deleteMany`（见 `smoke-cleanup-devdb.mjs`）。

## 二、后端 API（`/api/v1/pet`，均 `authRequired`）

### 基础互动

- `GET /pet` —— 取或自动创建，返回**含衰减后**的实时状态 + 派生 `state`（`happy/hungry/dirty/sleepy/sad`）。
- `POST /pet/action { action: feed|play|clean|sleep }` —— 先折算衰减再叠加动作，写回并升级，返回新状态。
  - feed: 饱食+25、心情+5、清洁-5、exp+10、coins+2
  - play: 心情+20、精力-15、清洁-8、exp+15、coins+3
  - clean: 清洁+40、心情+3、exp+5
  - sleep: 精力+50、饱食-5、exp+5
  - 响应含 `levelUp: boolean` 与 `evolutionJustUnlocked` 字段（见进化体系）
- `POST /pet/rename { name }` —— 1-12 字，超长 422。
- `POST /pet/play-game { game:'catch'|'poke'|'memory', score }` —— 小游戏结算奖励：金币 `+ceil(score/2)`、经验 `+score`，叠加衰减后数值并自动升级；`mood+5 / energy-3` 微调；`score=0` 时返回成功但不额外奖励。

### 每日签到

- `POST /pet/checkin`
  - 同一天重复签到返回 `409 今日已签到`
  - 连续天数：上一次签到日期为"昨天"则 `streak+1`，否则重置为 `1`
  - 奖励公式：`base(5 + min(streak-1,6)*2) + levelBonus(min(level,10))`
  - 成功返回 `{ coins, award, base, levelBonus, streak, total, checkedInToday }`
  - **不**更新 `lastUpdated`（避免干扰四维衰减时钟）

### 成长进化

- `GET /pet/evolution`
  - 返回：`level, exp, expToNext, currentStage, currentStageIndex, nextStage, nextLevelNeeded, unlockedStages, totalStages`

### 装扮商店（`/api/v1/pet-shop`）

| 端点 | 说明 | 关键校验 |
| --- | --- | --- |
| `GET /api/v1/pet-shop` | 目录 + 当前用户 coins / owned / equipped；每项含 `unlockLevel` 与 `locked` | `authRequired` |
| `POST /api/v1/pet-shop/buy` | 购买（事务扣币 + 建持有记录） | 已拥有→409；余额不足→400；不存在→404；未达等级→403 |
| `POST /api/v1/pet-shop/equip` | 装备已拥有装扮（同槽切换） | 未拥有→400 |
| `POST /api/v1/pet-shop/unequip` | 卸下某槽位 | `slot` 枚举校验 |

> 防双花：`/buy` 必须用事务 `updateMany` with `where coins >= cost`，避免并发双花（见 project_memory Hard Constraints）。

代码：`src/routes/pet.routes.ts`、`src/routes/pet-shop.routes.ts`、`src/lib/petShop.ts`、`src/lib/petEvolution.ts`，挂载于 `src/index.ts`。

- `PetPage` 完整模式头部「桌面显示」按钮（仅 `isDesktop()` 显示）调用 `togglePetWindow` 重新唤出浮窗。

## 五、成长进化体系

### 进化阶段（成长里程碑）

配置位置：`backend/src/lib/petEvolution.ts`

| 等级阈值 | 阶段 key | 形态名 | 光环 |
| --- | --- | --- | --- |
| Lv1 | baby | 幼崽 | 无 |
| Lv3 | grow | 成长体 | ✨ |
| Lv5 | mature | 成熟体 | 🌟 |
| Lv8 | full | 完全体 | 💫 |
| Lv12 | legend | 传说体 | 👑 |

- `getEvolution(level)`：返回当前阶段、下一阶段（含所需等级）、已解锁阶段列表。
- `evolutionUnlockedBetween(from, to)`：判断升级是否跨越进化阈值，用于升级时返回"刚刚进化"提示。

### 装扮等级解锁门槛

配置位置：`backend/src/lib/petShop.ts`（`PetShopItem.unlockLevel`，默认缺省 = 1 = 无门槛）

| 商品 | 解锁等级 |
| --- | --- |
| 棒球帽 / 绅士帽 / 墨镜 / 书呆子镜 / 蝴蝶结 / 骨头 / 弹力球 / 樱花背景 | 1（无门槛） |
| 海洋背景（稀有） | Lv3 |
| 星空背景（稀有） | Lv4 |
| 皇冠（史诗） | Lv5 |
| 钻石项圈（史诗） | Lv6 |

### 等级特权

| 特权 | 规则 | 实现 |
| --- | --- | --- |
| 签到加成 | `levelBonus = min(level,10)` | `pet.routes.ts` `/pet/checkin` 返回 `base` / `levelBonus` |
| 装扮解锁 | 商店 `GET /pet-shop` 返回 `locked = pet.level < unlockLevel`；`POST /buy` 校验未达等级返回 **403** | `pet-shop.routes.ts` |
| 进化可见 | 升级跨越阈值时返回 `evolutionJustUnlocked`，前端播放进化提示 | `pet.routes.ts` `/pet/action`、`/pet/play-game` |

> 互动动作本身不直接加等级加成（保持状态条语义清晰），等级特权主要体现在**签到金币**与**装扮解锁**两条线。

## 八、已知限制 / 后续

- 浮窗宠物与主页宠物**状态已后端同步**，宠物浮窗带 **15s 轮询**自动刷新
- 3D 为程序化基础造型（球体生物），未做骨骼/表情纹理；后续可换 glb 模型
- 小游戏「接食物 / 逗一逗 / 记忆翻牌」三种**已实现得分→金币/经验奖励闭环**，但计分未做跨会话持久化
- 宠物金币（游戏币）与 `wallet`（RMB 钱包：balance/frozen/支付密码）是**两套独立货币**，互不影响
- Electron 真机 GUI 仍受沙箱缺 `electron.asar` 限制，签到/商店/进化均为纯逻辑层已由冒烟覆盖
- 可选后续：① 进化形态在 3D 本体上的视觉差异（换肤/特效）；② 等级特权扩展（专属互动动作/经验加成）；③ 跨会话宠物排行榜（等级/形态榜）
