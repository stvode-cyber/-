代码规范

适用所有写代码场景 · AI 触及写代码即加载 · 可直接打印张贴

一、代码风格

通用

  • 缩进：2 空格（禁用 Tab）
  • 引号：单引号 ' '
  • 分号：必加
  • 换行：LF
  • 编码：UTF-8

TypeScript / JavaScript

  • 用 const / let，禁用 var
  • 用 === 严格相等，禁用 ==
  • 用箭头函数（对象方法除外）
  • 用模板字符串，禁用字符串拼接

二、命名规则

类型规则示例
变量驼峰，见名知义userAge, fetchData
函数动词开头getUser(), sendEmail()
类帕斯卡UserService, OrderModel
常量大写下划线MAX_RETRY, API_BASE
文件小写连字符user-service.ts
布尔is/has/can 开头isReady, hasPermission

函数命名动词表

动词用途
get / set查 / 改
add / update / delete加 / 更新 / 删
fetch / save / load远程取 / 持久化 / 读本地
create / build / parse / format新建 / 组装 / 解析 / 格式化

三、文件组织

单文件限制

  • 一个文件 ≤ 300 行
  • 一个函数 ≤ 50 行
  • 一个文件只做一件事

模块结构

模块名/
├── README.md           ← 模块说明
├── xxx.routes.ts       ← 路由
├── xxx.service.ts      ← 业务逻辑
├── xxx.model.ts        ← 数据模型
└── xxx.test.ts         ← 测试

四、注释规范

必写

  • 函数：说明"干啥的" + 参数 + 返回值
  • 复杂逻辑：说明"为什么"
  • TODO：标记未完成项
  • 安全相关：说明风险点

不用写

  • 显而易见的代码（let count = 0）
  • 命名已说清的（getUserById(id)）

注释格式

/**
 * 查用户信息
 * @param userId - 用户ID
 * @returns 用户信息对象
 */
function getUser(userId: string) { ... }

五、错误处理

必须处理

  • 外部输入：校验类型 / 范围 / 格式
  • 异步操作：try/catch 或 .catch()
  • 空值：用可选链 ?. 或默认值 ??
  • 边界：数组越界、除零、溢出

正确示例 推荐

try {
  await saveUser(user);
} catch (err) {
  logger.error('保存用户失败', err);
  throw new Error('保存失败，请重试');
}

反面示例 禁止

try { ... } catch (e) {}  // 吞掉错误，不要这样写

六、安全规范

绝不能做

  • 不写死密钥 / token / 密码（用环境变量）
  • 不拼接 SQL（用参数化查询）
  • 不执行用户传入的代码
  • 不信任前端输入（后端必须校验）
  • 不在日志里打印密码 / 敏感信息

必须做

  • 密码加密存储（bcrypt）
  • JWT 放 HttpOnly Cookie
  • 文件操作校验路径（防目录穿越）
  • 用户输入做转义（防 XSS）
  • 每个敏感接口做权限校验

七、TypeScript 特定规范

类型

  • 禁用 any（必须用 unknown 替代）
  • 优先用 type 定义联合类型，interface 定义对象
  • 函数必须标返回类型
  • API 响应有统一的 Response<T> 类型

导入导出

  • 用 ES Module（import/export）
  • 禁用 CommonJS（require / module.exports）
  • 按需导入，禁用 import * as
