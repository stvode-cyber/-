### 一、修复：不确定性表达误触任务创建

**问题**：用户说"明天不知道做什么好"时，AI 回复"好的，明天要不知道做什么好。帮你安排一下："，直接触发了任务创建流程，没有先确认用户意图。

**根因**：`ai-reply.ts` 中 `TASK_ACTION_KEYWORDS` 正则包含单独的"做"字，会匹配"做什么"中的"做"；`extractTaskTitle` 也没有过滤不确定性短语。

**修改文件**：
- `backend/src/lib/ai-reply.ts`
- `backend/src/services/llmService.ts`

**具体改动**：

1. **新增不确定性短语检测**（`ai-reply.ts`）
   - 新增 `UNCERTAINTY_PATTERNS` 正则数组，匹配"不知道做什么"、"无聊"、"不知道干嘛"、"有什么推荐的"等 11 种不确定性表达
   - 新增 `isUncertaintyExpression()` 函数
   - 在 `detectTaskCreation()` 函数最开头调用，命中则直接返回 null，走 LLM 闲聊路径

2. **优化任务关键词**（`ai-reply.ts`）
   - 从 `TASK_ACTION_KEYWORDS` 中移除"做"、"安排"、"约"等过于宽泛的单字
   - 改用"要做"、"帮安排"、"约了"、"要约"等精确组合词
   - 新增"有场"、"去参加"、"去面试"等更具体的组合

3. **extractTaskTitle 增加不确定性过滤**（`ai-reply.ts`）
   - 函数开头调用 `isUncertaintyExpression()`，命中返回 null
   - 增加 noisePhrases 过滤残留的不确定性短语

4. **LLM 系统提示加强**（`llmService.ts`）
   - 新增对话规则 11-13：
     - "先确认再行动：用户说'不知道做什么'时，先问清楚想干嘛"
     - "不替用户做决定：用户没明确说要做某事，别自作主张创建任务"
     - "模糊表达要追问：用户说'明天有事'但没说什么事，追问一句"
   - "主动帮忙"部分新增：不确定性表达先问清楚再帮

**测试结果**：
- "明天不知道做什么好" → AI 回复"是要加班还是..."（text 类型，先确认意图）
- "明天下午3点开会" → 正常触发任务创建卡片（task_options_card）
- "无聊啊，不知道干嘛" → AI 自然聊天建议（text 类型）

### 二、选项2 Electron 真机验证（阻塞，根因精修）

**现状复核**：`electron/node_modules/electron` 已装、`dist/electron.exe`(v33.4.11, 188MB) 存在，但 **`dist/electron.asar` 缺失** → `require('electron').app` 为 `undefined`，主进程无法启动。

**根因（比上一轮更精确）**：`github.com` 本身可达（HTTP 200）；但 release 302 重定向到的二进制 CDN `release-assets.githubusercontent.com` 被防火墙拦截（`curl -sL` 跟随重定向得 `http=000`），故 `electron.asar` 在本沙箱**无法下载补全**。即"整机断网"不成立，是 GitHub release 二进制 CDN 被墙。

**解锁条件**：需在能访问 GitHub release CDN 的机器上 `npm install electron` 补全 `electron.asar`（或预置 `electron.asar`），再 `npm start` 实跑 GUI。

**修改文件**：
- `DAM_LITE_DESIGN.md`（已知风险表"Electron 真机 GUI 验证"行，改为精确根因）
