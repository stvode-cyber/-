# 新协作规范落地 SOP（Bootstrap）

## 🔴 触发时机（精确关键词，匹配即触发）

| 用户说 | 触发？ |
|---|---|
| "好的，按这个方案来" / "好的按这个来" | ✅ 触发 |
| "执行吧" / "开干吧" / "做吧"（紧跟在给了新规范之后） | ✅ 触发 |
| "回过你才动" / "逻辑图过" / "回字母再动" | ✅ 触发 |
| 单纯"好的"（没给新规范上下文） | ❌ 不触发 |

---

## 🔴 核心原则

**职责切清**：
- 本 SKILL = **怎么把新规范落地**（流程工具人）
- collab-25-rules SKILL = **规范内容是什么**（规则本身）
- 两个独立，绝不合并

**两段式铁律**：一段对话只干一件事（铁律 23）——方向段只定不动手，执行段三样缺一不许动。

---

## 🔴 五步执行流程（前两轮实战验证）

### 第一步：读 + 复述（方向段开始）

```
1. 回复开头打「已读设定」
2. 逐条复述用户给的新规范要点（归类提炼，等用户点头）
3. 跑分档尺子（Z/Z+/A/B）→ 量化表：文件数/行数/动接口/新依赖/对外/熟不熟/变动情况
4. 出方向卡六格（目标/范围/边界/产出/风险/验收）
5. 出 A 保守 / B 平衡 / C 激进三套推演
6. 出组合逻辑图（节点+输入+判定分叉+出口+回滚点）
7. 跑正推 + 反推
8. 跑随机失败轨道（真错一次，说清怎么炸/怎么发现/怎么退回）
9. 摆 5 个竞品实据（必须有 1 个失败退场案例）
10. 每条结论带来源标签（实测/文档/联网/你说的/推理）
11. 登记 REG-xx（负责人+到期+未覆盖）+ GAP-xx（缺的点）
12. 等用户拍板（方案字母 + 回「过」）
```

### 第二步：执行段（用户点头后）

```
1. 复述方向卡六格 + 执行段三样（方向卡+文件清单+授权范围）
2. 逐个执行文件改动
3. 跑验证（门禁脚本/构建/类型检查）
4. 每完成一个标记 [x] 带证据
5. 遇到坑立即停下 → RCA 五步
```

### 第三步：踩坑闭环（RCA-xx 五步 · 铁律 19）

```
围堵（先填上不扩散）
  → 时间线（精确到分钟）
  → 因果图（无证据不上图）
  → 四层原因（表层→流程→系统→假设）
  → 对策带验证指标（写"怎么知道修好了"）
```

**落点必须判 A 规则 / B 工具 / C 案例，没落点不许关 RCA。产出 RT-xx 回归用例，只增不删。**

### 第四步：登记收口（铁律 20）

```
REG-xx 全登记 → 确认无遗漏
GAP-xx 写回流清单 → 下次开工先读
RCA-xx 全闭环 → 五步走完
RT-xx 全产出 → 下次同类动作必跑
```

### 第五步：台账 + 对话卡 + 进程版本（铁律 21/22）

```
1. 今日 daily.md 追加完整工作记录
2. 项目对话卡.md 倒序追加 DC-xx（写人话，进度带分母）
3. 项目进程.md 版本号 +0.1（v主.次）+ 改动影响记录
4. INDEX.md 更新（新增 SKILL / 文件索引）
5. 门禁脚本 check-readiness.ps1 重跑验证
```
