## 一、UX 反模式清单（Top 15）

> 按出现频率 + 伤害程度排序。绿角犀每个都应该扫一遍。

### P0 · 必改（破坏核心路径）

| # | 反模式 | 长啥样 | 怎么修 | 绿角犀扫描位置 |
|---|---|---|---|---|
| **AP-01** | **点了没反应** | 按钮能点但没 loading、没 toast、也不跳转 | 每个异步操作必须加 loading 状态 + 成功/失败 toast | 注册发送验证码、设置保存、AI 回复、备份 |
| **AP-02** | **无确认的危险操作** | 点删除直接删了，不给后悔 | 弹 Modal 明确说后果 + 双按钮（取消/确认删除） | 删除 Vault 条目、重置设置、卸载模块 |
| **AP-03** | **不可理解的错误消息** | "HTTP 500" / "操作失败" / "ECONNREFUSED" | 说人话 + 给解决建议 | 所有 catch 块、API error handler |
| **AP-04** | **表单提交后重置** | 用户填了 5 项，校验不过，全部清空 | 只清空校验失败的字段或保留所有值，高亮错误 | 注册表单、备份设置 |
| **AP-05** | **无限 spinner** | 请求超时了还在转，用户不知道是卡了还是网络断了 | 加超时兜底（10s）→ 失败 toast + 重试按钮 | AI 回复、云端同步、远程访问连接 |

### P1 · 应该改（增加认知负担）

| # | 反模式 | 长啥样 | 怎么修 | 绿角犀扫描位置 |
|---|---|---|---|---|
| **AP-06** | **双弹窗确认** | 点删除 → "确定删除？" → "再次确认，不可恢复" | 合并为一个弹窗，用危险按钮颜色 + 明确文案 | 备份删除（之前看到过这个！） |
| **AP-07** | **下拉菜单里 80% 都不选** | 下拉有 10 个选项，大多数用户永远用不到 | 低频选项收进"高级"折叠区；高频预填默认值 | AI 模型选择、备份频率、主题颜色 |
| **AP-08** | **相同信息填两次** | 注册填手机号 → 登录又填手机号（虽然这个是不同场景，但想想能不能自动关联？） | 登录页"已注册手机号直接登录"选项 | 登录/注册切换 |
| **AP-09** | **操作完要手动刷新** | 新建了一个 Vault 条目，列表不自动更新 | mutate 成功后自动 revalidate | Vault 列表、备份历史 |
| **AP-10** | **状态静默丢失** | 设置了深色模式，重启后变回去了 | 所有偏好必须持久化到 localStorage + 启动时读 | 主题、语气、AI 模型 |
| **AP-11** | **布局溢出** | 窄窗口时按钮跑到屏幕外或横向滚动条出现 | 加 `overflow-x-hidden` + 小窗口断点重新布局 | 设置页子 tab、对话气泡 |

### P2 · 锦上添花（体验细腻度）

| # | 反模式 | 长啥样 | 怎么修 | 绿角犀扫描位置 |
|---|---|---|---|---|
| **AP-12** | **按钮颜色无语义** | 取消和删除都是蓝色 / 确认和次要操作同色 | 绿色=成功/确认、红色=删除/危险、primary=主要、灰色=次要 | 全应用所有按钮 |
| **AP-13** | **空状态只有空列表** | Vault 空了 → 显示"暂无数据"就完了 | 空状态 = 为什么空 + 引导操作按钮 | Vault、备份历史、对话列表 |
| **AP-14** | **tooltip 覆盖关键内容** | 悬停提示挡在操作按钮上 | tooltip 方向朝屏幕内侧，别挡目标 | 图标按钮、help 图标 |
| **AP-15** | **禁止的操作没说为什么** | 保存按钮灰着但不知道为什么 | 按钮灰 + tooltip "请先勾选协议" / "验证码 6 位" | 注册勾协议前注册按钮灰着、设置未填完保存灰着 |

## 二、一键化机会识别规则

> 核心思想：**用户能少点一下就少点一下。能自动就别让用户手动。**

### 规则 R · 识别维度

| 规则 | 判断 | 操作建议 | 优先级 |
|---|---|---|---|
| **R01 · 双步可合并** | 操作 A 完成后 90% 用户会做 B → 合并 | A 成功后自动执行 B 或提供一键 | P0 |
| **R02 · 弹窗确认消除** | 非破坏性操作不需要确认弹窗 | 去掉弹窗，直接执行 + toast 可撤销 | P0 |
| **R03 · 记忆上一次** | 同一设置用户不会每次都改 | 记住上次选择，下次打开直接预填 | P0 |
| **R04 · 自动刷新** | 操作完成后用户想看结果 | 状态自动更新，不需要手动点刷新 | P0 |
| **R05 · 默认值智能推断** | 可以根据用户上下文推断的不要让用户选 | 自动推断 + 提供"改一下"入口 | P1 |
| **R06 · 批量操作合并** | 3 个独立的设置项，用户可能同时改 | 合并为一个"场景切换"（如"一键夜间模式"） | P1 |
| **R07 · 中间页消除** | 列表 → 详情页 → 返回列表（只为看一眼） | 用 Drawer / Modal 直接弹出来，不路由跳转 | P1 |
| **R08 · 自动备份** | 用户不会记得手动备份 | 关键变更后自动触发一次轻量备份 | P1 |
| **R09 · 快捷键直达** | 高频功能点起来麻烦 | 给 Ctrl+Shift+N 这种全局快捷键 | P2 |
| **R10 · 状态同步** | 多窗口/多页面的状态不一致 | 用 Zustand persist 或 broadcast channel 同步 | P2 |

### 一键化机会输出模板

```markdown
### ⚡ 一键化机会：<页面/功能>

**当前**：N 步操作
**建议**：简化为 M 步 / 完全自动化
**命中规则**：R01 + R03
**复杂度**：低/中/高
**修复代码入口**：`<文件>:<行号>`

#### 操作对比
| 现在 | 之后 |
|---|---|
| 1. 打开设置 | 1. （自动完成） |
| 2. 切到备份 tab | |
| 3. 点立即备份 | |
| 4. 选路径 | |
| 5. 确定 | |
```

## 四、Nielsen 可用性启发式原则（完整版）

> **10 条经典原则 + 绿角犀实战检查点。**
> 每条都对应：原则说明 → 绿角犀检查点 → 常见违反 → 修复示例。

### N1 · 系统状态可见性（Visibility of System Status）

**原则**：用户执行任何操作后，系统必须在合理时间内给出反馈，告诉用户"发生了什么"。

**绿角犀检查点**：
- [ ] 按钮点击后有 loading 状态吗？（loading spinner / 文字变 "保存中..."）
- [ ] 保存成功有 toast 吗？（"已保存"，2s 自动消失）
- [ ] 错误有明确的错误 toast / modal 吗？
- [ ] 页面跳转有进度指示吗？（骨架屏 / loading bar）
- [ ] 长任务（备份、AI 生成）有进度条吗？

**常见违反**：点保存按钮 → 啥也没发生 → 用户再点一次 → 发两次请求

**修复**：按钮 `disabled={loading}` + `{loading ? '保存中...' : '保存'}`

---

### N2 · 匹配用户心智（Match Between System and Real World）

**原则**：界面语言、图标、概念必须是用户熟悉的。不要用系统内部术语。

**绿角犀检查点**：
- [ ] 按钮文案是用户的话吗？（"连接远程电脑" ✅ vs "启用 WebDAV 服务端" ❌）
- [ ] icon 是通用的吗？（🔔 通知 ✅ vs 🧩 module ❌ 除非是开发者工具）
- [ ] 时间格式是本地格式吗？（2026年9月14日 11:30 ✅ vs 2026-09-14T11:30:00Z ❌）
- [ ] 数字单位是对的吗？（1.2 MB ✅ vs 1258291 字节 ❌）

**常见违反**："AUTH_MODE: cloud-proxy" 作为设置项显示给用户

**修复**：显示 "云端账号模式"，内部用 "cloud-proxy"

---

### N3 · 用户控制与自由（User Control and Freedom）

**原则**：允许用户撤销操作、退出当前流程、修改之前的输入。不要让用户感觉被困住。

**绿角犀检查点**：
- [ ] 危险操作有确认弹窗吗？（删除 / 重置 / 切换安全设置）
- [ ] 可撤销操作有 Undo 吗？（Toast 上加 "撤销" 按钮）
- [ ] 多步骤流程能后退吗？（注册途中按后退 → 安全返回上一步）
- [ ] 流程中间能取消吗？（"关闭" / "取消" 按钮始终可见）
- [ ] 表单能清空重填吗？

**常见违反**：设置了深色模式想改回去，找不到入口在哪

**修复**：设置页每个 tab 都放一个 "恢复默认"

---

### N4 · 一致性与标准（Consistency and Standards）

**原则**：同类型的元素必须长得一样、行为一样、颜色一样。不要让用户每次都重新学习。

**绿角犀检查点**：
- [ ] 确认按钮都是绿色 / primary 色？
- [ ] 取消按钮都是次要色？
- [ ] 危险按钮（删除）都是红色？
- [ ] 同类 icon 尺寸一致？
- [ ] toast 出现位置、消失时间一致？
- [ ] Modal 关闭方式一致（右上 X / ESC / 点击遮罩）？

**常见违反**：设置页保存是绿色，备份确认也是绿色，但删除按钮也是绿色

**修复**：删除按钮 → `className="...bg-red-600 text-white"`

---

### N5 · 错误预防（Error Prevention）

**原则**：好的错误提示不如不让错误发生。在用户操作前就拦住明显的坑。

**绿角犀检查点**：
- [ ] 手机号输入有格式校验吗？（11 位数字，1 开头）
- [ ] 验证码框限制 6 位数字吗？
- [ ] 密码强度有实时提示吗？（至少 8 位，含字母数字）
- [ ] 提交按钮在必填项没填完时禁用吗？
- [ ] 重复点击有防抖吗？
- [ ] URL 输入自动补 `https://` 吗？
- [ ] 数字输入有 min/max 限制吗？

**常见违反**：注册时协议没勾，点注册 → 啥也没发生（用户不知道为什么）

**修复**：协议没勾 → 注册按钮 disabled + tooltip "请先同意用户协议"

---

### N6 · 识别而非回忆（Recognition Rather Than Recall）

**原则**：把需要记住的信息展示出来，不要让用户去回忆"我之前选了啥"。

**绿角犀检查点**：
- [ ] 设置页当前选项高亮了吗？（当前主题、当前 AI 模型、当前语气）
- [ ] 登录后显示当前账号名了吗？
- [ ] Vault 显示最近修改时间了吗？
- [ ] 多设备登录 → 显示所有活跃设备了吗？
- [ ] 上下文始终可见？（不管在哪个页面，都知道自己是"用户3"、当前在"对话"tab）

**常见违反**：切到高级设置 → 用户忘记自己之前改成啥了

**修复**：设置项旁边显示"当前值"

---

### N7 · 灵活与高效（Flexibility and Efficiency of Use）

**原则**：给新手简单模式，给老用户快捷方式。高级选项默认折叠，不干扰新手。

**绿角犀检查点**：
- [ ] 高频操作在显眼位置？
- [ ] 低频操作收起来了吗？（"高级" / "更多" / Settings 子 tab）
- [ ] 有键盘快捷键吗？（Ctrl+N 新对话、Ctrl+Enter 发送）
- [ ] 老用户能跳过新手引导吗？
- [ ] 有"快速设置"（3 个最常用的）和"完整设置"区分吗？

**常见违反**：设置页放了 30 个选项，新手看了懵，老用户也找不到自己要的

**修复**：默认只显示 8 个最常用的，其他收进"高级"tab

---

### N8 · 美观与极简（Aesthetic and Minimalist Design）

**原则**：界面只放**当前任务需要**的元素。其他的收起来。每屏不超过 5 个主操作按钮。

**绿角犀检查点**：
- [ ] 当前页面有 ≥ 6 个主按钮？→ 需要精简
- [ ] 有没有和当前任务无关的装饰性元素？
- [ ] 同一段信息有没有重复展示？
- [ ] 标题 / 副标题 / 正文层次清晰吗？
- [ ] 留白足够吗？（元素之间不挤）

**常见违反**：首页同时显示天气 + 倒计时 + 每日问题 + 今日打卡 + AI 对话入口 + 宠物 → 信息过载

**修复**：用户可自定义首页卡片，默认只显示 3 个最重要的

---

### N9 · 帮用户认错（Help Users Recognize, Diagnose, and Recover from Errors）

**原则**：错误消息要说人话、说清楚问题、给解决建议。不要只说 "Error" 或 "HTTP 500"。

**绿角犀检查点**：
- [ ] 错误消息包含：**发生了什么 + 为什么 + 怎么办**？
- [ ] 技术错误有降级显示吗？（内部 log 记详情，用户只看友好消息）
- [ ] 网络错误 → "网络似乎断了，请检查网络连接" + 重试按钮
- [ ] 服务器错误 → "服务器暂时不可用，请稍后再试" + 重试按钮
- [ ] 表单校验错误 → 高亮错误字段 + inline 说明

**常见违反**：`{"code":500,"message":"ECONNREFUSED"}` 原样显示给用户

**修复**：
```typescript
// 后端 catch → fail(res, '连接云端身份源失败，请检查网络或稍后再试', 502)
// 前端 catch → toast('网络连接异常，请检查网络后重试')
```

---

### N10 · 帮助与文档（Help and Documentation）

**原则**：用户不该去翻 README。最小化的 inline help 应该在需要时就在那。

**绿角犀检查点**：
- [ ] 设置页关键项有 `?` tooltip 吗？（hover 显示说明）
- [ ] 空状态有引导文案吗？（"还没有 Vault 条目，点右下角 + 添加一个"）
- [ ] 第一次用新手引导吗？（3 步，可跳过）
- [ ] 复杂功能有视频/动图演示吗？（远程访问、AgentCore）
- [ ] 帮助中心入口好找吗？（设置页底部 / Ctrl+? 快捷键）

**常见违反**：远程访问功能，用户不知道 WebDAV 是什么、端口怎么填

**修复**：`?` tooltip → "让另一台电脑通过文件管理器访问你的绿角犀数据。端口默认 3900，修改后需要重启。"
