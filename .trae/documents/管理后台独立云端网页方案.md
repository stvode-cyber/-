# 管理后台独立成云端网页 + 移除桌面端管理入口

## Context（背景）

管理后台目前作为 **桌面 APP 的一个内部路由**（`/admin/*`）存在，入口藏在登录页底部链接，且打包进客户端。用户希望：
1. 管理后台**不再依附于 APP 分发**，独立成一个可由浏览器访问的**云端管理网页**。
2. 桌面 APP 内**完全移除管理后台入口**。
3. 部署形态采用已确认的**"后端托管管理页"**方案（云端 Express 静态托管，浏览器同源访问 `/admin`，/api/v1 同源 + HttpOnly Cookie 认证，不加 Nginx）。

## 现状（已核实）

- 管理后台前端已是独立路由：`frontend/src/App.tsx` L200-225 在 `pathname.startsWith('/admin')` 时独立渲染 `AdminLayout`（自包含侧边栏、权限校验、登出）。
- `AdminLayout.tsx` 完全复用 `useAuthStore` + `ConfirmDialog` + lucide-react，无 AppShell 依赖，可脱离主 APP 单独运行。
- 登录是普通 user/管理员共用接口；未登录访问 `/admin` 会 `Navigate /login`。
- Web 浏览器模式 `api.ts` 用相对 `/api/v1` + **HttpOnly Cookie** 认证（`platform.ts` 判定 web → `useHeaderAuth=false`），后端 `setAuthCookie` 已下发 HttpOnly cookie，`authRequired` 优先读 cookie。同源访问不触发 CORS。
- 后端 `backend/src/index.ts` **当前无 express.static**，但 Express 自带静态托管能力；`"type":"module"` 需用 `import.meta.url` 取 `__dirname`。
- 后端 `.env` `CORS_ORIGIN="http://localhost:5173"` 单一来源白名单。
- 云端生产：`/root/backend`，PM2 `aie-backend`，端口 3001，`HOST=0.0.0.0` 公网直连。

## 推荐方案：独立 admin 构建产物（Vite 多入口），后端 `express.static` 托管

**为何不做"整份 dist 托管"（方案 A）**：管理网页会连带整个 APP（所有业务页 + PWA + Electron 专属逻辑），体积大、耦合深，且 `base:'./'` 在 `/admin` 深链下资源解析错位。选 **方案 B**：独立 HTML 入口，只打包 8 个管理页 + 认证，`base:'/admin/'`，产物放 `frontend/admin-dist/`（`dist` 的兄弟目录），与 Electron 打包（复制 `frontend/dist`）完全隔离。

## 改动清单

### 前端

1. **`frontend/src/App.tsx`**
   - 删除 L79-88 整段管理后台 lazy import（AdminLayout/Dashboard/Users/UserDetail/AuditLogs/Handovers/Community/AgentConfig/AbStats 共 9 个）。
   - 删除 L200-225 `if (location.pathname.startsWith('/admin'))` 整块分支。
   - 更新 L141-143 顶部注释，去掉"管理后台路由"条。
   - 生效范围：桌面端 + web 主 APP 均不再有 `/admin`（三端一致，符合"管理入口迁移到云端网页"）。

2. **`frontend/src/pages/LoginPage.tsx`**
   - 删除移动端 L432-434、桌面端 L624-626 两处"管理后台入口 →"链接。
   - 删除顶部 `Link` 导入（两处删除后 `Link` 无引用，避免 tsc 报 unused）。
   - 删除相关注释行（"5. 管理后台入口"一条）。

3. **新增 `frontend/admin.html`**
   - 精简 HTML：`lang=zh-CN`、`viewport`、`title="绿角犀 · 管理后台"`、`<div id="root">`、`<script type="module" src="/src/admin-main.tsx">`。不挂 PWA manifest。

4. **新增 `frontend/src/admin-main.tsx`**（独立管理入口）
   - 复用：`AdminLayout` + 8 个 admin 页（直接 import，无需懒加载）+ `LoginPage` + `useAuthStore` + `ConfirmDialog` + `ErrorBoundary` + `./index.css`。
   - 用 `BrowserRouter`（云端 http 源走 web 模式，**不用** HashRouter）。
   - 渲染前 `useAuthStore.getState().init()`。
   - **不调用** `initServerConfig()`（避免 localStorage 残留自定义服务器 URL 覆盖相对 `/api/v1`）。
   - 路由：
     ```
     <Route path="/admin" element={<AdminLayout />}>
       8 个子路由（与现在一致）
     </Route>
     <Route path="/login" element={<LoginPage />} />
     <Route path="*" element={<Navigate to="/admin" replace />} />
     ```
   - 外层补 `<Toaster />`（AdminLayout 只自带 ConfirmDialog，toast 需自己加）。

5. **新增 `frontend/admin-vite.config.ts`**（独立构建）
   - `base: '/admin/'`、`plugins: [react()]`、**不引入 VitePWA**、`build.outDir: 'admin-dist'`、`build.rollupOptions.input: admin.html`、`emptyOutDir: true`。
   - `frontend/package.json` 增脚本 `"build:admin": "vite build --config admin-vite.config.ts"`。

### 后端

6. **`backend/src/index.ts`** — 加静态托管 + SPA fallback，位于所有 API 挂载之后、`app.use(notFound)` 之前：
   ```ts
   import path from 'path'
   import { fileURLToPath } from 'url'
   const __dirname = path.dirname(fileURLToPath(import.meta.url))
   const adminWebDir = process.env.ADMIN_WEB_DIR || path.join(__dirname, '..', 'public', 'admin')
   app.use('/admin', express.static(adminWebDir, { index: 'index.html' }))
   app.get('/admin/*', (_req, res) => res.sendFile(path.join(adminWebDir, 'index.html')))
   ```
   - 生产目录 = `backend/dist` 的上级 `backend/public/admin`（即 `/root/backend/public/admin`）。
   - CORS 不改（同源不触发）；桌面 Electron 不需托管管理页（入口已移除）。

## 认证链路（无需后端改动）
`GET /admin` → 静态壳 → admin-main init → 无 cookie 跳 `/login` → `POST /api/v1/auth/login` 同源 Set-Cookie(HttpOnly) → `navigate('/')` → `*`→`/admin` → AdminLayout 校验 `role==='admin'` 进入 → 各页相对 `/api/v1/admin/**` 自动带 cookie。

## 构建 / 部署 / 验证

**本地构建**
```bash
cd frontend && npm run build          # 主 APP（Electron/web），已移除 admin
cd frontend && npm run build:admin    # 独立管理网页 → frontend/admin-dist/
```
**云端同步（Linux，47.116.59.141）**
```bash
# 后端改完后重新编译：cd /root/backend && npm run build（本地 npx tsc 编译后 scp dist，与既有流程一致）
# 上传管理页产物，先清空旧目录再拷贝
scp -r frontend/admin-dist/* root@47.116.59.141:/root/backend/public/admin/
# 重启
cd /root/backend && pm2 restart aie-backend
```
**桌面端重打包**：`npm run build` 后照既有 Electron 打包流程生成新安装包（resources/frontend/dist 不再含 admin 入口）。

**验证**
```bash
curl -s http://47.116.59.141:3001/admin | head            # 返回 admin index.html
curl -s -o /dev/null -w "%{http_code}\n" http://47.116.59.141:3001/admin/users   # SPA fallback 200
curl -s http://47.116.59.141:3001/api/v1/auth/me          # 未带 cookie → 401（API 未被误吞）
```
浏览器无痕：开 `http://47.116.59.141:3001/admin` → 跳登录 → 管理员登录 → 8 菜单可点、各页/API 200 带 cookie；深链刷新 `/admin/users` 不 404；非管理员登录显示"权限不足"。启动桌面版 & web 主 app，确认无"管理后台入口"、`/admin` 不可达。

## 注意事项
- 后端 ESModule：`__dirname` 用 `import.meta.url`，勿直接用全局 `__dirname`。
- `admin-main.tsx` 勿调 `initServerConfig`。
- 删除入口后必须删 `Link` 导入。
- admin-vite 不引 PWA；`emptyOutDir` 指向 `admin-dist` 不会误删 `dist`。
- 上传管理页前先清空服务器 `public/admin` 旧文件，避免残留旧 hash 资源。
