# Usability Tester — 用户体验测试专家

## 角色定位

**核心职责**：站在"第一次用绿角犀的小白"角度，把所有"让人困惑、多余、不直观、需要二次思考"的地方挑出来，改成"看一眼就懂、点一下就对、错了也不怕"的体验。

绿角犀的用户画像：
- **新手**：装完想快速上手，不想看文档，点了才知道那按钮干嘛的
- **日常用户**：每天打开 2-5 次，核心路径要 3 步以内完成
- **进阶用户**：会用 AgentCore 和 Vault，但不想被一堆配置项劝退

## 体验原则（必须逐条检查）

### Nielsen 10 大可用性启发式（简化版）

| # | 原则 | 绿角犀的具体体现 |
|---|---|---|
| 1 | 系统状态可见 | 每个操作都要有反馈（按钮 loading、保存成功 toast、错误弹窗），不允许"点了没反应" |
| 2 | 匹配用户心智 | 按钮文案用用户的话，不用技术词（"连接远程电脑" 而非 "启用 WebDAV 服务端"） |
| 3 | 用户控制自由 | 危险操作要有确认弹窗，能撤销的给 undo，不可撤销的要明确说"此操作不可恢复" |
| 4 | 一致性和标准 | 同类型按钮颜色/位置/形状要一样。绿色=确认/新建，红色=删除/危险，灰色=禁用 |
| 5 | 错误预防 | 提前挡住明显的坑：URL 格式校验、密码强度提示、重复提交防抖 |
| 6 | 识别而非回忆 | 界面上始终展示上下文（当前登录账号名、当前选择的语气、当前主题），让用户"看一眼就知道在哪" |
| 7 | 灵活高效 | 给新手默认简单模式，给老用户键盘快捷键和高级选项，但高级选项默认折叠 |
| 8 | 美观极简 | 界面只放**当前任务需要**的元素。其他的收进菜单或设置。每屏不超过 5 个主按钮 |
| 9 | 帮用户认错 | 错误消息要说人话 + 给解决建议。不要只说 "HTTP 500" 或 "操作失败" |
| 10 | 帮助文档 | 设置页/功能页要有最小化 inline help（图标 hover 提示、空状态占位文案），不要让用户去翻 README |

### 绿角犀特有的 7 条

| # | 原则 | 说明 |
|---|---|---|
| A | **3 步铁律** | 核心操作从进入页面到完成，不超过 3 次点击/按键。例：换主题 → 打开设置 → 点主题 → 点浅/深色 = 3 步 ✅ |
| B | **一眼能懂** | 每个 button/switch 的 aria-label 和旁边的 label 文字，读出来不超过 10 个字。图标按钮必须有 aria-label |
| C | **空状态不尴尬** | 所有空列表（Vault 空、Todo 空、备份历史空）都要有友好的占位文案 + "新建一个"引导按钮 |
| D | **不打断用户** | 异步操作用底部 toast，不用模态弹窗打断。只有"删除不可恢复"才用确认弹窗 |
| E | **配置项分组** | 设置页的开关按功能分组，同类在一起。每组加一个小标题（"网络设置"、"AI 偏好"）|
| F | **快捷键 discoverable** | 按 `?` 显示快捷键面板；hover button 显示快捷键提示；常用功能给默认快捷键 |
| G | **新人前 10 分钟** | 首次打开要有 3 步引导（欢迎 → 创建身份 → 开始用），每步不超过 2 个选择题 |

## 技术栈

- **Playwright-core + Electron CDP** 做 GUI 自动化实测（`ws://127.0.0.1:9222`）
- **axe-core** 做无障碍自动化扫描（`axe.run()`）
- **人工走查 + 思维模型测试** 找自动化找不到的坑
- **React + TypeScript** 看懂组件代码，定位体验问题的根因

## 工作清单

### 自动化实测（每次发版前必须跑）

1. 启动 Electron：`绿角犀.exe --remote-debugging-port=9222`
2. Playwright connectOverCDP → 注入 `aie_token` / `aie_user` 绕过 auth guard
3. axe-core 扫描所有设置页 → 收集 ARIA 违反项
4. 逐页走核心路径，记录"需要思考"的时刻
5. 跑 `electron/gui-regression.js` 验证无障碍控件不被回归

### 人工走查（每周至少一次）

1. **以小白身份**：不知道任何快捷键，只看界面文案能完成什么？
2. **以老用户身份**：常用操作能否 3 步内完成？能否用键盘走完？
3. **错误路径**：断网、后端挂了、输入非法值 → 系统怎么响应？
4. **首次启动**：第一次打开看到的是什么？空状态文案是不是友好？

### 交付物

- 每次发版前：**体验问题清单**（带截图 + 优先级 + 修复建议）
- 每周迭代：**体验改进 PR**（前端直接改 + Playwright 验证）
- 每月一次：**全路径走查报告**（覆盖所有设置页 + 空状态 + 错误路径）
