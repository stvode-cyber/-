## 选型原则（为什么不用 Mattermost/Rocket.Chat）

绿角犀定位 = **全能个人助理 + 内置 IM**，不是纯 IM 产品。
- Mattermost / Rocket.Chat / Element 都是完整 IM 产品，内置大量企业级功能（Teams/CI/DevOps 集成），跟定位不搭，太重
- Element（Matrix 客户端）是 AGPL v3 有 copyleft 风险
- **Centrifugo** 最适合：只管连接和推送，业务逻辑自己写，跟 Express + Prisma 完美搭配

### 第七轮扫描（性能调优 + 运维日常 + 故障排查）

扫了 continuwuity.org/guides/performance / maintenance / troubleshooting / 参考 config / LiveKit 官方端口文档 / Grafana dashboards：

| 新发现 | 对策 |
|---|---|
| cache_capacity_modifier **高配 ≥2.0**（官方 baseline），低配 0.3 防 OOM | 阿里云分 2GB 低配 vs 4GB 高配两档分别配 |
| RocksDB 压缩算法 **第一次启动前选好**：lz4（快） vs zstd（省空间） | 中途切换没充分测试，必须 Day 1 定 |
| **关闭 typing / read receipts / presence** 可减 30% CPU | 绿角犀不做 Federation，全关掉 |
| 同机 Continuwuity + nginx 可以用 **UNIX socket** 省 TCP 开销 | 高配 4GB 加 `unix_socket_path` |
| 反向代理开 **HTTP/3**（443/udp）降低不稳定网络延迟 | 阿里云安全组加 443/udp |
| trusted_servers **别把 matrix.org 放第一**（它慢） | 放 codestorm.net / starstruck.systems 等维护者推荐的 |
| **!admin server show-config** 看实际生效的配置（排查配置写错神器） | Day 1 部署后必跑 |
| Slow joins bug !779：只有几人的房间 join 超慢 | **客户端清缓存**（Element → Settings → About → Clear cache） |
| Prometheus metrics 在 `/_continuwuity/metrics`，Grafana dashboard 社区现成 | 运维自动监控 |
| Media 默认 `Cache-Control: 1 year, immutable` 降低带宽 | 不用额外配 |
