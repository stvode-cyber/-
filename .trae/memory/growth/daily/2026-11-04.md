### [nginx HTTPS 443 两 bug —— 精准定位 + 补丁]

**现象**：服务器 curl 4 条链路测试：

| 链路 | 修复前 | 修复后 |
|---|---|---|
| HTTP 80 API | ✅ 200 | ✅ 200 |
| HTTP 80 APK | ✅ 200, 16.4MB | ✅ 200, 16.4MB |
| HTTPS 443 API | ❌ **502 Bad Gateway** | ✅ 200 |
| HTTPS 443 APK | ❌ **404 Not Found** | ✅ 200, 16.4MB |

**Bug 1: HTTPS 443 API 502 Bad Gateway**

根因：nginx location 优先级规则。HTTPS 443 block 里同时存在：
```nginx
location ^~ /api/v1/ {           # ← 前缀匹配，优先级高，proxy_pass 3100
    proxy_pass http://127.0.0.1:3100;
}
location ~ ^/api/v1/app/ {       # ← 正则匹配，被 ^~ 抢走，proxy_pass 3101 永远到不了
    proxy_pass http://127.0.0.1:3101;
}
```

Nginx 规则：`^~`（前缀 + 不走正则）> `~`（正则）。
所以 `/api/v1/app/android-version` 被 3100 吞了 → 502（3100 没开）。

修复：正则改前缀 + 位置提前
```nginx
location ^~ /api/v1/app/ {       # ← 改前缀 ^~，优先级高于 ^~ /api/v1/
    proxy_pass http://127.0.0.1:3101;
}
location ^~ /api/v1/ {           # ← 放在 /api/v1/app/ 之后
    proxy_pass http://127.0.0.1:3100;
}
```

**Bug 2: HTTPS 443 APK 404 Not Found**

根因：HTTPS 443 block 里的 `/apk/` 配错了：
```nginx
location ^~ /apk/ {
    proxy_pass http://erp_backend;   # ← 错！3000 端口的 ERP 后端没有 APK
}
```
而 HTTP 80 block 里的 `/apk/` 是对的：
```nginx
location ^~ /apk/ {
    root /usr/share/nginx/html;      # ← 直接静态文件
}
```

修复：HTTPS 的 `/apk/` 改成跟 HTTP 一样的 root 静态文件。

**补丁执行链**：
```
本地写 fix-nginx-https.py → base64 分块上传服务器 → python3 /tmp/fix-nginx.py → nginx -t ✅ → nginx -s reload ✅
```
备份：`/etc/nginx/conf.d/default.conf.bak-20261104`
