## 发现的重大新坑

### NestJS → Express 反转（动作 ① 发现）
- **现象**：secrets.md 说"后端是 NestJS，没挂 /health"
- **实测**：本地 `backend/package.json` **零 NestJS 依赖**，`index.ts:133` 明写 `app.get('/health', ...)`
- **根因**：不知何时（可能初始或某次误写）把 Express 后端错写成了 NestJS
- **影响**：8 个活跃文件被误导，"没挂 /health → 404 正常"这个判断完全反了
- **修正**：全项目改 NestJS→Express，改"没挂 /health"→"挂了 /health"
- **预防**：以后**任何时候**说框架名前，先看 package.json dependencies

### PowerShell 批量删多行 console.log 留垃圾（动作 ② 踩坑）
- `console.log(\`[FetchJobScheduler]...\`)` 被 PowerShell 的 `$_ -notmatch '^\s*console\.log\('` 只删了 `console.log(` 这一行开头
- 后面的字符串参数和闭合 `)` 留在文件里，造成 TS1109 语法错
- **修**：手动删残留行
- **教训**：PowerShell -replace 删多行 JS 语句不安全，应该逐文件 Read + Edit

### PowerShell 删除 ChatPage interface 块时混入尾巴（动作 ④ 踩坑）
- 原本 ChatPage.tsx 行 323-394 是 ChatSessionItem interface 的尾巴 + 空行 + 注释
- PowerShell `$lines[322..393]` 保留时带进来了 `errorMsg/createdAt/updatedAt }` 四行 interface 垃圾
- **修**：手动删行 17-20 残留
- **教训**：用 PowerShell 精准切分代码块前，先确认文件结构再写行号

### HandoverPendingItem 重复定义（动作 ④ 踩坑）
- 原本 ChatPage.tsx 有两处 HandoverPendingItem：一处在 chatTypes.ts 的 MessageMetadata 引用，一处在 1684 行的独立定义
- 拆分时 PowerShell 抽取 MsgAvatar 到末尾的范围（1528-2794）包含了 1684 行的独立定义
- 加了 import 之后，同名 interface 在同一文件定义两次 → 冲突
- **修**：删掉 ChatWidgets.tsx 里的重复定义，保留 chatTypes.ts 的唯一真相源

### release-v16 旧目录被锁（动作 ⑤ 踩坑）
- `query_engine-windows.dll.node` + `d3dcompiler_47.dll` 被 Defender/其他进程锁
- electron-builder EnsureEmptyDir 删不掉 → ERR_ELECTRON_BUILDER_CANNOT_EXECUTE
- **解法**：换 `--config.directories.output=release-v17` 指定新目录打包绕过
- **教训**：打包前如果旧 release 目录存在，直接指定新目录名更省时间
